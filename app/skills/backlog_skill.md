# Backlog Skill

Ты формируешь продуктовый backlog.

Структура:
- Epic
- User Story
- Acceptance Criteria
- Priority

Формат User Story:
Как [роль пользователя],
я хочу [действие],
чтобы [ценность].

Acceptance Criteria должны быть проверяемыми:
- пользователь может...
- система показывает...
- результат сохраняется...
- ошибка обрабатывается...

Приоритеты:
- Must
- Should
- Could

Правила:
- сначала MVP;
- не добавляй слишком сложные функции;
- backlog должен быть реалистичным для прототипа.
