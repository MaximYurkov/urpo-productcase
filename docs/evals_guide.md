# Evals Guide

## 1. Зачем нужны evals

Evals нужны, чтобы оценивать качество работы LLM и агентной системы не только субъективно, а по заранее заданным критериям.

В ProductCase AI evals используются для проверки того, что система действительно проходит основные этапы продуктового анализа и формирует нужные блоки продуктового кейса.

## 2. Что оценивается

В проекте оценивается не только финальный текст, а совокупный результат работы всех агентов.

Проверяются результаты:

- Planner Agent;
- Market Analyst Agent;
- Product Manager Agent;
- Critic Agent;
- Report Writer Agent.

Это важно, потому что маленькая локальная модель может не всегда идеально собрать финальный отчёт, но промежуточные результаты агентов всё равно показывают работу workflow.

## 3. Файлы evals

Тестовые кейсы находятся в файле:

`evals/test_cases.json`

Скрипт запуска оценки:

`evals/run_evals.py`

Результаты сохраняются в файл:

`evals/eval_results.json`

## 4. Тестовые кейсы

В проекте используются несколько продуктовых идей:

- сервис анализа отзывов клиентов малого бизнеса;
- AI-сервис подбора рекламных креативов;
- приложение для студентов и дедлайнов.

Каждый кейс содержит:

- id теста;
- описание идеи;
- список обязательных ключевых слов.

## 5. Метрика оценки

В MVP используется простая keyword-based метрика.

Система проверяет, есть ли в результатах агентов ключевые блоки:

- целевая аудитория;
- JTBD;
- Lean Canvas;
- MVP;
- backlog;
- roadmap;
- риски;
- критика.

Score считается как доля найденных обязательных ключевых слов.

Пример:

Если нужно найти 7 ключевых слов, а найдено 5, score будет примерно 0.71.

## 6. Порог прохождения

В MVP тест считается пройденным, если score больше или равен 0.5.

Такой порог выбран потому, что проект использует лёгкую локальную LLM `gemma2:2b`, которая может формулировать разделы не всегда одинаково. Цель evals в текущей версии — проверить прохождение ключевых этапов workflow, а не идеальное качество текста.

## 7. Пример результата

Пример результатов после запуска evals:

- b2b_reviews — score 0.71, passed true;
- ad_creatives — score 0.83, passed true;
- student_tracker — score 0.5, passed true.

## 8. Как запустить evals

Перед запуском нужно убедиться, что Ollama работает.

Команда запуска Docker:

`docker compose up -d`

Команда запуска evals:

`python -m evals.run_evals`

После выполнения результат появится в файле:

`evals/eval_results.json`

## 9. Ограничения текущих evals

Текущая система оценки простая и имеет ограничения:

- она проверяет наличие ключевых слов, а не глубокий смысл ответа;
- она не оценивает фактическую точность рыночных гипотез;
- она не проверяет качество Lean Canvas экспертно;
- она не сравнивает ответ с эталонным решением;
- она не использует LLM-as-a-judge.

## 10. Что можно улучшить

В следующих версиях можно добавить:

- ручную экспертную оценку;
- LLM-as-a-judge;
- сравнение с эталонными ответами;
- отдельные метрики для каждого агента;
- hallucination score;
- faithfulness score;
- completeness score;
- регулярный запуск evals при изменении промптов;
- сохранение динамики качества по версиям.
